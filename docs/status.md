### Отличия от каркаса Oracelk

Оба файла на сервере правлены руками, рядом лежат `*.scaffold-backup`.

**`nginx.conf` — заменён на сплошной прокси.** Каркас отдаёт `/static/` и
`/media/` сам, из томов. Для нашего сайта это смертельно: 76 МБ обложек лежат
в образе, и платформенный nginx перехватывал бы весь префикс `/media/`, отдавая
из пустого тома — все картинки работ стали бы битыми. Ни сборка, ни локальный
тест этого не ловят, поломка видна только после выката.

**`docker-compose.yml` — убраны тома `media` и `static`.** После замены конфига
они ни на что не ссылались, но продолжали монтироваться в оба сервиса и вводили
бы в заблуждение.

## Образ

Multi-stage: `node:24-alpine` собирает, `nginx:1.27-alpine` отдаёт на **:8000**.

- **99.8 МБ**, из них 79 МБ — медиа отдельным слоем. Задумано, чтобы правка
  текста пушила килобайты, но пока хеш этого слоя меняется на каждой сборке, и
  выкат гоняет все 78 МБ заново — B-31.
- `absolute_redirect off` — обязательно. Контейнер слушает 8000, публичный сайт
  на 443; без этого `/works/syrnik` отвечал бы `301` на `http://…:8000/…`,
  мёртвый за туннелем.
- `try_files $uri $uri/index.html $uri/ =404` — именно в таком порядке, иначе
  индексный модуль редиректит вместо отдачи.
- Кеш из одной `map`: год для хешированных `/_astro/`, сутки для `/media/`,
  ревалидация для html и `/i18n/`, `no-store` для `/admin/`.
- `403` свёрнут в `404`, иначе каталог без индекса запинает в браузере годовой
  immutable-ответ об ошибке.
- `/healthz` для HEALTHCHECK и для возможного http-health модуля Oracelk.
- `.glb` отдаётся как `model/gltf-binary` и сжимается gzip: в стандартном
  `mime.types` этого типа нет, без правила модель уходила бы несжатой как
  `application/octet-stream`.

## 3D-лось и прелоадер

Spline больше не используется: лось рендерится напрямую через three.js.

| Файл | Что там |
|---|---|
| `src/scripts/elk-scene.js` | Сцена: камера, свет, материалы (matcap + смешивание, как было в Spline), анимация, поворот по скроллу, взгляд за курсором. Восстанавливается после потери WebGL-контекста. |
| `src/components/ElkScene.astro` | Канвас, переживающий навигацию. three.js грузится **только на главной**, на остальных страницах его нет вовсе. |
| `src/components/Preloader.astro` | Прелоадер «разобранный чертёж» из деталей логотипа. |
| `src/assets/elk/` | `elk.glb` (модель), `elk.meta.json` (размер для прогресса), matcap-текстуры — встраиваются в модуль сцены, отдельными запросами не ходят. |
| `scripts/build-elk-model.mjs` | Пересборка модели из `Brand/3D/los_anime1.glb`: `node scripts/build-elk-model.mjs`. |

**Вес на главной (gzip):** three.js 168 КБ + сцена с текстурами 15 КБ +
модель 82 КБ ≈ **265 КБ** против ~1,13 МБ у Spline. Прелоадер — 4,5 КБ.

**Обложки работ на главной грузятся лениво** (`loading="lazy"`, размеры читаются из
файлов при сборке). Раньше 8 PNG на 18 МБ грузились сразу и на медленном интернете
отнимали канал у сцены. Хуже того, первый `astro:page-load` у ClientRouter приходит
только по `window.load`, поэтому переключение языка, Rellax и курсор ждали все
картинки. Вёрстка сверена с прежней на 1440, 1024, 800 и 390 px: позиции плиток
и трансформы Rellax совпадают до пикселя.

**Как сцена сообщает о себе.** События на `window`: `elk:engine` (WebGL поднят),
`elk:progress` (доля скачанных байтов модели), `elk:ready` (первый кадр на
экране, с функцией проекции головы), `elk:error`, `elk:lost` / `elk:restored`.
Состояние дублируется в `.elk-stage[data-state]`: `loading` / `ready` / `lost` / `error`.
В обратную сторону страница шлёт одно событие — `elk:cover { image }`, см. ниже.

**Обложка проекта на лосе.** При наведении на работу на главной лось принимает
цвета её обложки (раньше он просто уходил в `mix-blend-mode: overlay`).

- **Тело — гранёный камень в цветах проекта.** Обложка работает как matcap: цвет
  грани берётся из картинки по направлению нормали и лежит под светом и matcap
  тела на месте белой основы. Нормали у модели плоские, поэтому каждая грань
  получает цвет целиком, и растяжек нет. Свет нормирован на свою среднюю
  величину, иначе краски тускнели.
- **Как выбирали.** Женя сравнивал вживую пять вариантов: проекцию обложки из
  камеры (картинка узнаётся, но растягивается на гранях, повёрнутых ребром) и
  matcap по плоским и по сглаженным нормалям, каждый чистым и под светом тела.
- **Рога и копыта подкрашены цветом фона за ними.** Размытый фон страницы — та же
  обложка (`background-size: cover`, `blur(30px)`), поэтому шейдер берёт её цвет в
  той же точке экрана из мипмапа, равного размытию. Доля — `COVER.backdropTint`
  (0.55). Сверено: при доле 1.0 рога растворяются в фоне.
- Текстура берётся из уже загруженной `<img>` плитки: уменьшается до 1024 px вне
  главного потока и кешируется. Первое наведение на 10-мегабайтный Dotaboom —
  125 мс, дальше мгновенно.
- Проявление 750 мс с кривой `ease`, как у размытого фона. Между работами обложки
  перетекают друг в друга (два слота), при быстром проходе по плиткам
  промежуточные не мелькают. При reduced motion — без анимации.
- Только на устройствах с настоящим курсором. Уход на кейс кликом сбрасывает
  обложку, лось возвращается белым.

**Когда показывается прелоадер.** Только при полной загрузке главной и один раз
за сессию (`sessionStorage['elk-preloader']`). Переход на главную через
ClientRouter его не показывает и тоже ставит флаг. Если всё загрузилось быстрее
350 мс, чертежа нет вовсе — кремовая заслонка просто растворяется.

**Проверено в браузере 2026-09-16** на продакшн-сборке с искусственно медленной
сетью:

| Сценарий | Итог |
|---|---|
| Быстрая загрузка | кадр через ~125 мс, заслонка растворяется за 260 мс |
| Медленная (модель ~4,5 с) | вся сборка по вехам, щёки идут по реальным байтам, раскрытие от головы; ~2,4 с от готовности до конца |
| Готово после 6,5 с | короткий выход без перелёта; подпись и метки убраны вместе со знаком |
| Модель дольше 8 с | заслонка уходит по таймауту, лось проявляется, когда догрузится |
| 500 на модели, обрыв посреди скачивания, сбой модуля сцены | заслонка растворяется, страница рабочая, прокрутка разблокирована |
| Reduced motion, RU | ничего не летает, детали наливаются по вехам, подпись по-русски |
| Мобильный 390×844 | знак 160 px, точка раскрытия совпадает с головой |
| Прокрутка во время загрузки | колесо, PageDown, пробел, стрелки, End заблокированы; возвращаются в начале раскрытия |
| Slow 4G (~1,6 Мбит/с), телефон, через nginx из образа | кадр на 4,8 с, полная церемония, `window.load` на 9,2 с. До ленивых обложек: таймаут прелоадера, лось на 17–23 с, `window.load` на 94,6 с |
| Slow 4G, десктоп | кадр на 2,4 с, `window.load` на 1,0 с |

**Кеш на Cloudflare.** `.glb` не входит в список расширений, которые Cloudflare
кеширует по умолчанию, поэтому модель каждый раз идёт с сервера через туннель
(браузер при этом кеширует её на год). Лечится одним Cache Rule — B-29.

## Выкатка

**Деплоить по sha, никогда по `:latest`.** Oracelk выполняет
`docker compose up -d` без `--pull`, поэтому подвижный тег, уже лежащий на
хосте, не перекачивается: деплой отрапортует успех и молча оставит старый
образ. Оформлено обращением в Oracelk asks 2026-09-03.

Обычный цикл, когда B-24 будет снят:

1. Пуш в `main` → workflow `image.yml` собирает, прогоняет smoke-тест, пушит.
2. Взять тег из сводки запуска (короткий sha).
3. `set_project_image` — проект `elkhovering`, образ `ghcr.io/elkhovering/elkhovering-com:<sha>`.
4. `deploy_project`.
5. При проблемах — `get_project_logs`.

Пока CI не пушит, то же самое руками:

```bash
docker build -t ghcr.io/elkhovering/elkhovering-com:$(git rev-parse --short HEAD) .
gh auth token | docker login ghcr.io -u Elkhovering --password-stdin
docker push ghcr.io/elkhovering/elkhovering-com:$(git rev-parse --short HEAD)
```

### Что проверяет CI перед пушем

Контейнер поднимается и опрашивается — это ловит отказы, которых сборка не
видит: nginx на не том порту, потерянный слой медиа, редирект вместо отдачи на
`/works/syrnik`, `index.html` вместо 404. Если хоть что-то не так, в реестр не
уезжает ничего.
